## Key Commands

```bash
# Start development servers
npm run dev          # Runs both backend and frontend

# Backend only
cd backend && npm run dev

# Frontend only
cd frontend && npm run dev

# Regenerate service protocol (after changing protocols)
cd backend && npm run proto
# Or: npx tsrpc-cli proto --input ./src/shared/protocols --output ./src/shared/protocols/serviceProto.ts
```

## Critical: Auto-Generated Files

⚠️ **NEVER manually edit these files** - they are auto-generated:

- `backend/src/shared/protocols/serviceProto.ts` - Generated by `npm run proto`

To modify APIs, edit the `Ptl*.ts` protocol files, then run `npm run proto` to regenerate.

## Working with TSRPC

### Creating a New API

1. Create protocol file: `backend/src/shared/protocols/Ptl{Name}.ts`
2. Create API handler: `backend/src/api/Api{Name}.ts`
3. Run `cd backend && npm run proto` to regenerate serviceProto

### Protocol Naming Convention

- Protocol file: `Ptl{ApiName}.ts`
- Request interface: `Req{ApiName}`
- Response interface: `Res{ApiName}`

## Type Safety

TSRPC automatically validates request data against TypeScript types at runtime. This means:

- No need for manual validation of type structure
- Invalid requests are rejected before reaching API handlers
- Focus business validation on logic, not type checking

## Common Patterns

### API Implementation

```typescript
export async function ApiExample(call: ApiCall<ReqExample, ResExample>) {
    // Access validated request
    const { param } = call.req;

    // Success response
    call.succ({ result: 'value' });

    // Error response
    call.error('Error message', { code: 'ERROR_CODE' });
}
```

### Client API Call

```typescript
const result = await client.callApi('Example', { param: 'value' });
if (result.isSucc) {
    console.log(result.res);
} else {
    console.error(result.err.message);
}
```
